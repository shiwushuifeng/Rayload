# 局域网连接向导（v1.0.5）

用户已确认的三项决策（2026-11-17）：

1. **入口**：只在「局域网设备」页加一个「连接设备」按钮，首次引导（onboarding）不加这一步。
2. **默认首屏**：以「搜索局域网」为默认，扫码和手动地址作为备选。
3. **诊断深度**：要做自检，覆盖权限、同网段、端口连通、对方是否开启服务四类原因。

## 现有能力（不要把已经能用的东西重写）

- 二维码展示：`LanDevicesView.vue` 用 `qrcode` 生成配对码。
- 局域网扫描：`lan_scan` 命令 + `pairDiscovered(address)`。
- 手动配对：`lan_pair(address, username, password)`。
- 指纹确认：配对请求弹窗里已显示设备名与公钥指纹。
- 设备管理：改名、备注、颜色（颜色现在按设备身份派生，见 `deviceColors.ts`）。

## 向导流程

1. **本机准备**：显示本机设备名、监听端口；局域网权限被拒时给「去系统设置」的直达按钮。
2. **选择方式**（默认搜索）：搜索局域网 / 扫二维码 / 手动地址，三者互斥展示，不再并列堆按钮。
3. **核对身份**：显示对方设备名 + 公钥指纹，输入配对账号与密码。
4. **对方确认**：提示在另一台设备点确认，带超时倒计时与「重试」。
5. **完成**：可设备注与颜色（默认用身份派生色），可选「推送一个测试任务」验证链路通。

## 失败诊断（比流程本身更重要）

每种情况给一句可执行建议，而不是弹 `lan_` 原始错误：

| 原因 | 判定方式 | 给用户的建议 |
| --- | --- | --- |
| 局域网权限被拒 | 权限状态查询 | 去系统设置开启本应用的局域网权限 |
| 不在同一网段 | 本机/对方地址与掩码比较 | 确认两台设备连的是同一个 Wi-Fi |
| 端口不通 | 对目标端口做一次短超时连接 | 检查对方应用是否在运行、防火墙是否放行 |
| 对方未开启局域网服务 | 配对接口返回未启用 | 让对方打开「局域网设备」页并保持前台 |
| 指纹不一致 | 比对配对返回的公钥指纹 | 视为可疑，建议取消并核对设备 |

## 验收标准

- 全新安装 → 局域网设备页 → 连接设备 → 搜索 → 配对 → 完成，全程不需要退出向导。
- 断网、权限拒绝、对方未开启服务三种场景都能给出对应提示。
- 向导可随时关闭，关闭后设备页状态与手动路径一致。
