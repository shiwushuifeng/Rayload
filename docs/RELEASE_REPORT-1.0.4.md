## 一、结论先行

v1.0.4 是 Rayload 从「能下载」走向「可信、可控、可脚本化」的一版。三项主要交付：

1. **高级校验系统** —— 七种算法、SQLite 缓存、在线比对、下载后自动校验，把「下完了」变成「下对了」。
2. **真机交互与响应式布局** —— 滑动、配色、平板三处真实缺陷被定位并修复，Mobile/Tablet/Desktop 三档布局统一。
3. **可脚本化的 CLI** —— 稳定退出码、批量操作、`watch` 实时跟随，让 headless 场景真正可用。

配套工程化：GitHub Actions 首次跑通（此前 5 次运行全部失败），签名密钥与工具链版本落地，v1.0.4 已由 CI 从 tag 构建并发布。

## 三、模块一：高级校验系统

### 3.1 为什么做

下载工具的通病是「下完了不等于下对了」。分片损坏、镜像篡改、CDN 缓存污染都可能产生一个能打开但内容错误的文件。校验是这个环节唯一可靠的兜底。

### 3.2 交付内容

**算法**：MD5 / SHA-1 / SHA-256 / SHA-512 / BLAKE3 / SM3 / CRC32，七种。
单次读盘完成全部所需算法，不重复 IO；用户只勾选自己用的，未启用不计算。

**缓存**：SQLite 表 `file_hash_cache`，以「路径 + 大小 + 修改时间」为键、每算法一行。未变化的文件秒回，新增算法只补算缺失部分；文件被改写会因 size/mtime 变化自动失效。

**自动校验**：下载完成后按分类过滤自动比对，只对已公布摘要的来源执行，无误时不打扰用户，不一致则告警。

**允许/拒绝规则**：支持通配符与正则，`allow` 可覆盖更宽的 `deny`。

**在线查询**：先读 GitHub Release 资产自带的 digest，再查 CIRCL Hash Lookup；默认仅对 GitHub 来源发起，避免无谓外联。

**交互**：期望值粘贴即比对（对勾/叉）、运行中可取消、可导出 `.sha256` 形式校验文件、BT 多文件可逐个计算。

### 3.3 设计取舍

- **不做「全算法默认开启」**：SHA-512 与 BLAKE3 对普通用户无意义，默认只开 MD5/SHA-1/SHA-256/SHA-512 之外的常用集。
- **在线查询默认关闭对非 GitHub 来源的请求**：减少隐私暴露面。
- **缓存以文件版本为键而非内容哈希**：避免"为了查缓存而先算哈希"的循环依赖。

## 四、模块二：真机交互修复

### 4.1 滑动失效（最有价值的一次排查）

**现象**：模拟器可滑动，真机不行，且无震动反馈。

**排查路径**：
1. 无震动 → 手势未达 48px 阈值 → 不是阈值问题，是手势被中途掐断。
2. 用户补充「卡片会轻微抖动或跑出一点，然后弹回」→ 确认手势启动了再被取消。
3. 定位到 Android WebView 在列表滚动接管时派发 `pointercancel`，而原实现收到 cancel 即复位。

**修复**：改用 `touchstart`/`touchmove`/`touchend` 驱动，`touchmove` 用**非 passive** 监听，横向锁定瞬间 `preventDefault` 从滚动手里抢回手势；越过阈值的 `touchcancel` 按完成处理而非弹回。另加 12px 死区与 1.2 倍轴向优势比，容忍指尖抖动。

### 4.2 设备配色三处不一致

**现象**：同一台设备在设置页、任务卡、详情页显示三种颜色。

**根因**：不同视图用了不同的回退策略——设置页取 `deviceColors[id] ?? 主题色`，任务卡走**哈希调色板**，而任务里的 `deviceId` 与设置页的 `device.id` 不一定是同一字符串，于是同一设备算出不同哈希。

**修复**：取消哈希调色板，统一到单一解析函数 `resolveDeviceColor(...keys)`，按 id → name 顺序匹配；颜色统一为**扁平 hex**（未设置时由设备身份 FNV-1a 派生唯一色相），存储时同时写设备名别名。取色器读同一值，所见即所得。

### 4.3 其他交互修复

| 问题 | 修复 |
| --- | --- |
| 卡片「文件详情」紧贴文件名 | 固定到行尾，加分隔线 |
| 设置保存/放弃在最上方 | 改为底部停靠条，滚动时始终可达 |
| 已完成本地任务无法分享 | 右滑触发系统分享 |
| 完成提示有两个按钮 | 只保留「在文件夹中显示」 |
| 传输卡片溢出 | 修复碎片图首帧宽度为 0 导致负画布、残留过宽画布 |

## 五、模块三：响应式布局

| 断点 | 布局 |
| --- | --- |
| < 768px（手机） | 设置页横向 Tab + 分组卡片流；表单改为分隔行（去掉每项卡片外壳） |
| ≥ 768px（平板） | 两列布局，右栏限宽 860px 居中 |
| ≥ 900px（宽屏） | 统计页「全部设备」的实时速度与七天趋势并排 |
| 全宽屏 | 任务卡、统计磁贴、看板统一 1120px 限宽居中 |

**踩过的坑**：布局在 `≤900px` 塌成单列，而顶部 Tab 在 `≤768px` 才出现，导致 769–900px 区间（平板竖屏）出现「纵向列表 + 表单」叠层。统一到 768px 单一断点后消失。

**平板另一处缺陷**：所有设置表单写死 `label-width="260px"`，控件被挤出屏幕。改为随视口收缩（96/150/200/260px）。

## 七、模块五：CLI

### 7.1 改进前

`ray` 只能手工使用：所有错误统一退出码 1，`add` 一次一个 URL，`pause/rm` 必须给完整 GID，没有跟随模式。脚本无法判断"守护进程没起"和"真的失败了"。

### 7.2 改进后

**稳定退出码**

| 码 | 含义 |
| --- | --- |
| 0 | 成功 |
| 1 | 通用失败 |
| 2 | 用法错误 |
| 3 | 守护进程未运行或无响应 |
| 4 | 无匹配任务 |
| 5 | 凭据被拒 |

实现上从连接错误与 HTTP 状态分类得出：`error sending request`/`connection refused` → 3，超时 → 3，401/403 → 5。

**全局参数**：`--json`、`-q/--quiet`、`--color auto|always|never`（`NO_COLOR` 仍生效）。

**批量添加**：`ray add` 支持多 URL 或 `--input-file`（含 `-` 读 stdin），跳过空行与 `#` 注释；单个失败不中断其余，但整体仍非零退出；批量全为连接失败时保留退出码 3。

**选择器**：`pause`/`resume`/`rm` 支持完整 GID、≥4 位唯一前缀、`all`。

**新增 `watch`**：持续刷新任务表直到全部结束，`--interval-ms` 调频率，`--json` 每拍一行。

**稳定化**：所有 JSON 输出带 `schemaVersion`，字段改名不会静默打断下游脚本。

### 7.3 未完成

`shell 补全`（`clap_complete`）因构建环境无法从 crates.io 拉取新依赖而暂缓，已从代码中移除避免留下半成品。其余八项全部完成。

## 八、工程化

### 8.1 CI：从来跑不通到自动发布

排查发现 GitHub Actions 此前 **5 次运行全部失败**，三个独立故障：

| # | 故障 | 修复 |
| --- | --- | --- |
| 1 | `android-actions/setup-android@v3` 执行 `sdkmanager tools`，该包已从 SDK 仓库移除 | 不再依赖该 action，直接暴露 runner 自带 SDK 路径 |
| 2 | 平台包名 `platforms;android-37` 不存在（实为 `android-37.0`） | 改正 |
| 3 | 构建命令漏 `--features plugin_engine`，产物会隐藏局域网与插件入口 | 补上 |

另加防护：签名缺失时不再硬失败（转 unsigned 且跳过发布），并加 `workflow_dispatch` 便于验证链路。

**结果**：v1.0.4 由 tag 触发 CI 自动构建、签名、发布，8 个资产全部上传成功。

### 8.2 工具链锁定

`rust-toolchain.toml` 与 `.node-version` 入库，CI 从文件读取，本机与 CI 同源。

**一次自己造的坑**：最初把 `channel` 写死为 `1.100.0`，导致 rustup 每次调用都尝试重装该版本工具链，在慢速网络下把构建卡死十几分钟。改为 `channel = "stable"`（当前 stable 即 1.100.0），版本号以注释记录、由 CI 显式安装。

### 8.3 签名

三个 secrets 由本机 keystore 生成并通过 GitHub 公钥 sealed box 加密写入：
`ANDROID_KEYSTORE_BASE64`、`ANDROID_KEY_ALIAS`、`ANDROID_KEYSTORE_PASSWORD`。
CI 产物证书指纹与本机一致（`f4efa2df…0521bdb`）。

### 8.4 本地与 CI 产物的等价性

实测对比同一 commit 的两份产物：

| 内容 | 结果 |
| --- | --- |
| 包名 / versionCode / versionName / ABI | 一致 |
| 签名证书 SHA-256 | 一致 |
| `classes.dex` | 逐字节一致 |
| `lib/arm64-v8a/libaria2.so` | 逐字节一致 |
| `assets/data/*` | 逐字节一致 |
| `librayburst_lib.so` | **不同**：CI 含 85 处 `/home/runner` 绝对路径，内嵌前端 chunk 文件名哈希不同（Windows 与 Linux 的 Rollup 遍历顺序差异），体积差约 1.5 KB |

**结论**：不追求字节一致，以「版本 + 签名 + dex + sidecar + assets 一致」为验收口径。已确认功能等价。

### 8.5 构建环境（Windows 主机）

这台机器原本无法构建 Android 包，修复了五项：

1. 缺 MSVC C++ 工具链 → 安装 MSVC 14.44 + Windows SDK 10.0.26100
2. 工作区内编译的可执行文件被限制只能写工作区 → 产物目录外移到 `C:\rayload-build`
3. `esbuild` 在 `%TEMP%` 删临时文件被拒 → `TMP` 指向工作区内
4. 仓库缺 `src-tauri/data/cacert.pem` → 从 git 恢复
5. Tauri 插件 build script 写 `~/.cargo` 被拒 → 由第 2 项一并解决

## 十、经验与教训

**值得保留的做法**

1. **用反例缩小范围**：滑动问题靠"没有震动"这一条就排除了阈值因素，直接指向"手势被中断"。
2. **对照实验**：同一份二进制放工作区内/外做写入测试，把"沙箱限制"从猜测变成定论。
3. **先测再猜**：设备颜色三色问题的根因（id 与 name 不同键）是靠读代码发现两套回退策略才定位的，不是靠改样式试出来的。
4. **让 CI 成为唯一发布源**：Tag → 构建 → 签名 → 发布，可追溯性由流程保证，不依赖本机两次构建巧合相同。

**踩过的坑**

1. **自己加的工具链 pin 反过来卡住构建**（`channel = "1.100.0"` 触发反复下载）。
2. **husky 钩子在特定挂载下无法执行**，且 `pnpm install` 会重置 `core.hooksPath`，提交需带 `-c core.hooksPath=`。
3. **改了 `label-width` 一处却漏了其它表单**，说明这类重复配置应当收敛到一个 composable——最终确实是这么修的。
